2026年5月4日 - 第26课：RLHF 与人类对齐

今日学习主题

理解 ChatGPT 背后的秘密武器——RLHF（基于人类反馈的强化学习），掌握从「蛮力续写器」到「有用助手」的对齐流程。

为什么学这个？

上节课我们学了 AI 评估——知道了如何衡量模型好不好。但有个更根本的问题：怎么让模型变好？

你用过的 ChatGPT、Claude、Gemini，它们之所以能像「智能助手」一样工作，而不是像续写器一样胡说八道，核心秘密就是 RLHF。它不是锦上添花，而是从「能用」到「好用」的关键一跃。

作为架构师，理解 RLHF 帮助你： - 理解为什么不同模型的「风格」不同（对齐数据不同） - 评估一个模型是否做了充分对齐（安全性检查） - 理解 RAG、Agent 等应用为何需要在对齐模型之上构建

在 AI 演进中的位置：2017 年 OpenAI 发表 DRL 研究开始探索 RL + 语言模型的结合，2020 年 GPT-3 展示了 scale 的力量但仍是续写器，2022 年 InstructGPT 论文正式确立 RLHF 流程，2022 年底 ChatGPT 引爆全球——RLHF 是大模型从「研究玩具」到「生产力工具」的分水岭。

与前课的关系： - 上接第24课（推理模型）→ 模型有了推理能力 - 上接第25课（AI评估）→ 知道如何衡量效果 - 本课 → 理解训练过程的最后一公里：人类对齐

核心概念解释

1. 为什么需要对齐？

预训练语言模型本质上是一个条件概率模型：P(next_token | context)。它预测的是「下一个最可能的 token」，而不是「最有用的回答」。

直觉类比：一个读完全人类图书馆的天才，但没有社交经验。他能背出所有知识，但不知道： - 什么时候该简洁回答，什么时候该详细解释 - 什么请求应该拒绝（制造武器、诈骗教程） - 如何组织回答让读者快速理解

对齐就是教这个天才如何「沟通」。

2. RLHF 三阶段流程

阶段做什么输入输出类比
SFT监督微调(prompt, 理想回答) 对能回答格式正确的模型新员工培训手册
奖励模型训练偏好模型(prompt, chosen, rejected) 三元组打分函数 r(prompt, response)培养质检员
PPO强化学习优化模型 + 奖励模型对齐后的最终模型根据反馈持续改进

关键机制： - SFT 让模型学会「怎么回答」 - 奖励模型学会「什么回答好」 - PPO 让模型朝着「更好的回答」优化

3. 奖励模型（Reward Model）

奖励模型是一个回归模型，输入 (prompt, response) 对，输出一个标量分数。

训练数据来自人类标注：给标注者看同一个 prompt 下的两个回答，让他们选哪个更好。

训练目标：学习人类偏好排序

$$\text{loss} = -\mathbb{E}\left[\log\sigma(r(x, y_c) - r(x, y_r))\right]$$

其中 $y_c$ 是 chosen（好的回答），$y_r$ 是 rejected（差的回答），$\sigma$ 是 sigmoid。

直觉：让好回答的分数尽可能高于差回答的分数。

4. PPO 优化

有了奖励模型后，用它作为 reward signal 来做强化学习：

$$\text{objective} = \mathbb{E}_{x \sim \text{prompt}, y \sim \pi_\theta}\left[r(x, y) - \beta \cdot D_{KL}(\pi_\theta \| \pi_{\text{ref}})\right]$$

- $r(x, y)$：奖励模型给分 - $D_{KL}$：KL 散度惩罚，防止模型偏离原始模型太远 - $\beta$：惩罚系数

为什么要 KL 惩罚？ 防止 reward hacking——模型可能找到「钻空子」的方式获得高分，但实际回答质量下降。比如在回答末尾加一堆「完美」「excellent」之类的词来骗奖励模型。

5. DPO（Direct Preference Optimization）

2023 年提出的重要改进，跳过奖励模型训练和 PPO，直接用偏好数据优化策略模型：

$$\mathcal{L}_{\text{DPO}} = -\mathbb{E}\left[\log\sigma\left(\beta \left[\log\frac{\pi_\theta(y_c|x)}{\pi_{\text{ref}}(y_c|x)} - \log\frac{\pi_\theta(y_r|x)}{\pi_{\text{ref}}(y_r|x)}\right]\right)\right]$$

直觉：直接让模型在好回答上概率增大、差回答上概率减小，无需中间的奖励模型。

DPO vs RLHF 对比：

维度RLHFDPO
步骤SFT → RM → PPO (3步)SFT → DPO (2步)
训练稳定性需要调 PPO 超参更稳定

关键公式直觉

概念公式直觉解释
奖励模型损失$-\log\sigma(r_c - r_r)$好回答分数高于差回答 → loss 小
PPO 目标$r - \beta \cdot KL$获得高分，但不偏离原始模型太远
KL 散度$D_{KL}(P \Vert Q)$两个分布的「距离」，衡量偏离程度
DPO 损失$-\log\sigma(\beta(\Delta_c - \Delta_r))$直接拉开好/差回答的概率差距
SFT 损失$-\sum \log P(y_i \vert x)$标准语言模型损失，学会模仿理想回答

动手实践要点

- Notebook 中用简单文本特征模拟了奖励模型的打分逻辑 - 真实奖励模型是 Transformer 编码器 + 线性头 - PPO 训练曲线展示奖励上升 + KL 散度控制 - DPO 损失函数中 β 参数的控制效果直观可见 - 参数选择：β 通常在 0.1-0.5 之间，KL 惩罚系数需要根据模型大小调整

常见问题

Q: RLHF 和微调有什么区别？ A: 微调（SFT）是让模型学会「怎么回答」——模仿示例。RLHF 进一步让模型学会「什么是好回答」——根据人类偏好优化。微调是「看示例学习」，RLHF 是「根据反馈改进」。

Q: DPO 会完全替代 RLHF 吗？ A: 短期内不会完全替代。对于需要在线学习和迭代优化的场景，RLHF 仍然更灵活。但 DPO 因为简单稳定，在开源社区越来越受欢迎。很多现代模型（如 Llama 3）采用混合策略。

Q: 如果人类标注者有偏见怎么办？ A: 这是 RLHF 的核心挑战之一。解决方案包括：多样化标注者群体、明确标注指南、多轮标注交叉验证、Constitutional AI（用 AI 辅助评价）等。偏见问题没有完美解决方案，只能持续改进。

Q: 什么是 reward hacking？ A: 模型找到了「骗」奖励模型的方法，获得高分但实际回答变差。比如回答中加大量格式标记（列表、加粗）来获得高分，但内容空洞。KL 惩罚和人工抽检是主要防御手段。

本课总结

1. 对齐是必需的：预训练模型是续写器，RLHF 让它变成助手——这是 ChatGPT 爆火的核心秘密 2. 三阶段流程：SFT（学会格式）→ 奖励模型（学会评价）→ PPO（学会优化） 3. DPO 是简化版：跳过奖励模型，直接优化偏好，更简单更稳定 4. 关键挑战：人类偏见、reward hacking、标注成本
