核心概念介绍

1. 为什么需要「统一架构」？

第21课学的 CLIP 只解决了一半问题——它让图文在同一个嵌入空间里对齐（能检索、能打分），但它不能对话：你没法让 CLIP 像聊天一样「看图回答问题」。

真正的多模态助手（GPT-4V、Gemini）要的是：给一张图，模型像读文字一样读懂它，再用语言回答。

2. 关键洞察：一切皆 token

Transformer 本质上只认一件事——token 序列。文本经过 tokenizer 变成 token，图像经过视觉编码器 + 投影层也能变成 token。只要把它们拼成一条序列，Transformer 就能统一处理。

文本: [你好, 这张, 图里, 有, 什么]      ← 文本 tokenizer
图像: [v0, v1, v2, ..., vN]              ← ViT + 投影层 → 视觉 token
拼成: [<img>v0...vN</img>, 你好, 这张, 图里, 有, 什么]   ← 统一序列 → Transformer

3. 三种融合路线对比

路线 代表 做法 优点 缺点
拼接式 LLaVA 视觉 token 直接插到文本序列前面 实现简单、易训练 视觉 token 太多时序列很长
交叉注意力 Flamingo 视觉 token 通过 cross-attention 注入语言层 视觉 token 可压缩 架构更复杂
原生统一 GPT-4V/Gemini 从预训练起所有模态一起训、同一套参数 融合最深、上限最高 训练成本极高

4. Gemini 的「原生多模态」是什么意思？

GPT-4V 的早期版本接近「先训好语言模型，再接视觉」。而 Gemini 从预训练第一天就把图像、视频、音频和文本混在一起训练，所有模态共享同一套 Transformer 参数。这就是 Google 反复强调的 natively multimodal。

核心实现：最小化多模态统一模型

我们构建一个端到端的最小 demo，包含三个关键组件： 1. 文本 Embedding：把文本 token id 变成向量 2. 视觉编码器 + 投影层：把图像编码成与文本同维度的「视觉 token」 3. 统一 Transformer：吃下拼接好的「视觉 token + 文本 token」序列，用自注意力融合

这正是 LLaVA / GPT-4V 的骨架。投影层（Projector）是把视觉特征「翻译」成语言模型能理解的 token 的关键。

class VisionEncoder(nn.Module):
    """简化版视觉编码器：模拟 ViT 把图像编码成一串 patch 特征。
    输出维度 IMG_FEAT_DIM 与语言模型维度 D 不同，需要投影。"""
    def __init__(self, img_feat_dim=IMG_FEAT_DIM, num_tokens=NUM_VIS_TOKENS):
        super().__init__()
        # 用一个线性层模拟「图像 → patch 特征」的过程
        self.patch_embed = nn.Linear(3 * 8 * 8, img_feat_dim)  # 假设每个 patch 是 8x8 RGB
        self.num_tokens = num_tokens

    def forward(self, images):
        # images: (B, num_tokens, 3*8*8) 模拟切好 patch 的图像
        feats = self.patch_embed(images)   # (B, num_tokens, img_feat_dim)
        return feats


class VisualProjector(nn.Module):
    """投影层：把视觉特征翻译成语言模型的 token 嵌入。
    这是 LLaVA 的核心组件——MLP projector。"""
    def __init__(self, img_feat_dim=IMG_FEAT_DIM, d_model=D):
        super().__init__()
        self.proj = nn.Sequential(
            nn.Linear(img_feat_dim, d_model * 2),
            nn.GELU(),
            nn.Linear(d_model * 2, d_model),
        )

    def forward(self, visual_features):
        # (B, num_vis_tokens, img_feat_dim) -> (B, num_vis_tokens, d_model)
        return self.proj(visual_features)


class MultimodalPositionalEncoding(nn.Module):
    """统一的位置编码：视觉 token 和文本 token 共享同一套位置编号。"""
    def __init__(self, d_model=D, max_len=256):
        super().__init__()
        pe = torch.zeros(max_len, d_model)
        position = torch.arange(0, max_len).unsqueeze(1).float()
        div_term = torch.exp(torch.arange(0, d_model, 2).float() * (-math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        self.register_buffer('pe', pe.unsqueeze(0))

    def forward(self, x):
        return x + self.pe[:, :x.size(1)]

class UnifiedMultimodalModel(nn.Module):
    """最小化多模态统一模型 (LLaVA 风格)

    流程：
      图像 → 视觉编码 → 投影 → 视觉token
      文本 → token embedding → 文本token
      拼接 [视觉token, 文本token] → 加位置编码 → Transformer → LM Head
    """
    def __init__(self, vocab_size=VOCAB, d_model=D, num_heads=4, num_layers=2):
        super().__init__()
        self.vision_encoder = VisionEncoder()
        self.projector = VisualProjector()
        self.text_embed = nn.Embedding(vocab_size, d_model)
        self.pos_enc = MultimodalPositionalEncoding(d_model)
        # 统一的 Transformer：同时处理视觉和文本 token
        encoder_layer = nn.TransformerEncoderLayer(
            d_model=d_model, nhead=num_heads, dim_feedforward=d_model*4,
            batch_first=True, activation='gelu'
        )
        self.transformer = nn.TransformerEncoder(encoder_layer, num_layers=num_layers)
        self.lm_head = nn.Linear(d_model, vocab_size)

    def forward(self, images, text_ids):
        # 1. 视觉路径
        vis_feats = self.vision_encoder(images)            # (B, Nv, img_dim)
        vis_tokens = self.projector(vis_feats)             # (B, Nv, d_model)

        # 2. 文本路径
        text_tokens = self.text_embed(text_ids)            # (B, Nt, d_model)

        # 3. 关键一步：拼接成统一序列
        unified = torch.cat([vis_tokens, text_tokens], dim=1)  # (B, Nv+Nt, d_model)
        unified = self.pos_enc(unified)

        # 4. 统一 Transformer 处理（视觉和文本在这里通过自注意力互相「看见」）
        hidden = self.transformer(unified)

        # 5. 语言建模头：在每个位置预测下一个文本 token
        logits = self.lm_head(hidden)
        return logits, unified

# 实例化并验证前向传播
model = UnifiedMultimodalModel()
B = 2
dummy_images = torch.randn(B, NUM_VIS_TOKENS, 3*8*8)
dummy_text = torch.randint(0, VOCAB, (B, 6))

print(f'统一序列长度: {unified.shape[1]} = {NUM_VIS_TOKENS}(视觉) + {dummy_text.shape[1]}(文本)')
print(f'输出 logits: {logits.shape}  ← 每个位置都能预测词表中的下一个词')

深入理解：自注意力如何实现跨模态融合

统一架构的「魔法」就藏在拼接后的自注意力里。我们提取 Transformer 第一层的注意力权重，看看文本 token 如何「看」视觉 token。

GPT-4V / Gemini / LLaVA 架构对比

下面用结构化方式对比三者。注意它们的「统一程度」是递进的：

LLaVA (拼接, 模块化)  →  GPT-4V (深度联合训练)  →  Gemini (原生多模态, 从头一起训)
        简单                                        难，但融合最深
维度 LLaVA GPT-4V Gemini
视觉编码 冻结的 CLIP ViT 自有视觉编码器 原生多模态编码
投影层 MLP（训练） 联合训练 端到端统一
语言模型 Vicuna/LLaMA GPT-4 Gemini
训练阶段 先对齐再指令微调 联合预训练+对齐 所有模态从头混训
模态范围 图+文 图+文(+音频) 图+文+视频+音频
统一程度 模块拼接 深度联合 原生统一

演进趋势：从「拼接模块」走向「原生 Any-to-Any」——Meta 的 Chameleon 已经能在同一模型里输入图文、输出图文。

总结

  1. 统一架构的核心 = 一切皆 token：图像经 ViT+投影变成视觉 token，与文本 token 拼接，交给同一个 Transformer
  2. 自注意力天然实现跨模态融合：不需要专门的跨模态模块，文本 token 会自动「看」视觉 token
  3. 三种路线递进：LLaVA 拼接式 → GPT-4V 深度联合 → Gemini 原生统一，融合程度越来越深
  4. 投影层（Projector）是关键桥梁：把视觉特征翻译成语言模型能理解的维度
  5. 未来方向是 Any-to-Any：不仅能输入图文，还能输出图文（如 Chameleon）
