核心概念解释

1. 代码 Tokenizer — 代码不是普通文本

普通文本 Tokenizer 把句子切成词。但代码有独特结构：

  • 缩进有语法意义（Python 中 4 空格 = 代码块）
  • 空行分隔逻辑段落
  • 关键字高频出现（def、class、return 应该用短 token）

代码专用 Tokenizer 在 BPE 基础上增加了缩进编码、空行保留、关键字优先策略。

直觉类比： 切代码像切乐高——沿着凸起和凹槽切，而不是随意下刀。

2. FIM（Fill-in-the-Middle）— 补全不是续写

光标在函数体中间时，模型需要看到光标前后的代码。FIM 训练目标：

输入: <PREFIX> 前半段代码 <SUFFIX> 后半段代码
输出: 光标位置应插入的代码

直觉类比： 完形填空——给你文章的上半段和下半段，猜中间被挖空的部分。

这是 Codex 系列的核心训练任务，比纯续写更适合代码场景。

3. 代码 RAG — 让助手理解你的项目

Copilot Chat / Cursor 的核心技术之一。与通用 RAG 的关键差异：

维度 通用 RAG 代码 RAG
索引单位 固定长度文本块 函数/类/模块
检索策略 语义相似度 语义 + AST 结构 + 依赖关系
上下文组装 Top-K 拼接 函数 + 依赖 + 类型定义

4. Agent 模式 — 自主编程的循环

Plan → Code → Execute → Fix（循环直到成功或达到上限）

Claude Code / Devin 的工作方式： 1. Plan：将任务分解为子步骤 2. Code：逐步生成代码 3. Execute：在沙箱中运行，收集错误 4. Fix：根据错误信息修复代码，回到 Execute

关键公式直觉

概念 核心机制 直觉解释
代码 Tokenizer BPE + 缩进 token + 关键字短编码 像为代码定制的「语言切割器」
FIM 目标 P(middle | prefix, suffix) 给你上下文猜中间，而非给你开头猜结尾
代码 RAG Embedding 检索 + AST 感知 + 依赖追踪 不只找「看起来像」的代码，还找「逻辑上相关」的
Agent 循环 max_rounds: Plan→Code→Execute→Fix 像一个初级程序员：写代码→运行→看报错→改→再运行

动手实践要点

  • Notebook 中的 SimpleCodeTokenizer 演示了缩进和关键字的特殊处理
  • fim_completion 模拟了 FIM 补全的核心逻辑
  • CodeRAG 展示了函数级索引 + 依赖追踪的检索策略
  • MiniCodeAgent 实现了 Plan → Code → Execute → Fix 的完整循环

常见问题

Q: Copilot 补全和 ChatGPT 生成代码有什么本质区别？ A: 补全用 FIM 目标训练，理解光标前后上下文；ChatGPT 是纯续写模式。此外 Copilot 有代码库上下文（RAG），ChatGPT 只有对话历史。

Q: Agent 模式安全吗？让 AI 自主执行代码？ A: 安全防护是多层的：沙箱隔离（Docker）、权限控制（只读文件系统）、人工确认（关键操作需审批）、预算限制（最大执行轮数）。Claude Code 默认需要用户确认才能执行命令。

Q: Cursor 的 @file / @folder 功能是怎么实现的？ A: 本质是手动触发的 RAG——用户指定文件，系统将该文件内容注入 LLM 上下文。这比自动检索更精准，但需要用户知道该看哪些文件。

本课总结

  1. AI 编程助手 = 代码 LLM + FIM 训练 + 代码 RAG + Agent 框架，四层技术栈
  2. 代码 Tokenizer 针对代码结构优化，不是简单套用文本 Tokenizer
  3. FIM 是代码补全的核心训练目标，让模型能「填空」而非仅「续写」
  4. Agent 模式通过 Plan→Code→Execute→Fix 循环实现自主编程
  5. 选型建议：补全用 Copilot，理解项目用 Cursor，复杂任务用 Claude Code
