核心概念解释

1. 四大架构模式

模式 核心思路 复杂度 典型延迟
单次推理 输入 → 模型 → 输出 ⭐ < 500ms
RAG Pipeline 检索 + 生成 ⭐⭐ 1-3s
Agent Loop 规划 → 执行 → 观察循环 ⭐⭐⭐ 3-15s
Multi-Agent 多个专家 Agent 协作 ⭐⭐⭐⭐ 10-60s

直觉理解： - 单次推理 = 你问一个问题，AI 直接回答 - RAG = 你让 AI 先翻资料，再回答 - Agent = AI 自己决定要做什么、用什么工具、做几步 - Multi-Agent = 一组专家分工协作

2. RAG Pipeline 深入

RAG 是目前最成熟的 AI 应用架构，核心流程：

用户问题 → Embedding → 向量检索 → 重排序 → 拼装 Prompt → LLM 生成 → 返回

架构决策关键点：

决策点 选项 选型建议
分块策略 固定大小 / 语义分块 / 文档结构 优先语义分块，chunk size 256-512
向量模型 OpenAI / BGE / Cohere 中文场景 BGE 表现好
检索策略 稠密检索 / 稀疏检索 / 混合 混合检索效果最稳
重排序 无 / Cross-Encoder / LLM Rerank 准确率要求高时必须加
缓存 精确匹配 / 语义缓存 语义缓存可砍掉 60%+ 调用

3. Agent Loop 设计模式

Agent 的核心是 ReAct 循环（Reason + Act）：

Task → Thought → Action → Observation → Thought → ... → Answer

关键设计原则： - 每步必须有明确输出（Observation 不能为空） - 设步数上限（防死循环，通常 5-10 步） - 工具定义要清晰（名称 + 描述 + 参数 schema） - 结果必须有验证机制（不能盲目信任 LLM 输出）

4. 架构选型决策树

需要外部知识吗？
├── 否 → 单次推理
└── 是 → 需要多步推理吗？
    ├── 否 → RAG Pipeline
    └── 是 → 需要多种专业能力吗？
        ├── 否 → Agent Loop
        └── 是 → Multi-Agent

关键公式直觉

概念 公式/规则 直觉解释
余弦相似度 cos(a,b) = (a·b)/(|a||b|) 两个向量的方向一致程度，忽略长度
RAG 延迟 T_total = T_embed + T_retrieve + T_rerank + T_generate 四段累加，瓶颈通常在 generate
Agent 成本 Cost = Σ(LLM_calls × token_price) 步数越多越贵，所以要设上限
语义缓存命中 sim(query, cached_q) > threshold 相似度超过阈值就复用缓存结果

常见问题

Q: RAG 和微调该选哪个？ A: 需要最新知识或可追溯引用 → RAG；需要改变模型行为风格 → 微调；两者可以叠加使用。

Q: Agent 总是产生错误的行动计划怎么办？ A: 三招——(1) 改进工具描述让 LLM 理解正确用法；(2) 加入 few-shot 示例；(3) 增加结果验证步骤，不符合预期就重试。

Q: 多 Agent 系统比单 Agent 好在哪里？ A: 只有当任务天然可以分解为不同专业领域时才更好。否则多 Agent 的协调开销反而降低质量。不要为了用多 Agent 而用。

本课总结

  1. 四大架构模式：单次推理 < RAG < Agent < Multi-Agent，复杂度递增但适用场景不同
  2. 架构选型原则：先选最简单的，延迟和成本是硬约束，缓存是最好的优化
  3. RAG 是当前最成熟的模式：90% 的企业 AI 应用可以从 RAG 开始
  4. 可观测性是底线：没有 trace 和监控的 AI 系统等于黑盒
