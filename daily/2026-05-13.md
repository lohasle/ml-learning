**MLOps：从「训练出好模型」到「跑出好产品」——ML 系统的完整生命周期管理**

前 34 课我们系统学习了从线性回归到 Prompt Engineering 的 AI 技术栈。但一个残酷的现实是：**训练出好模型只是 AI 工程的 20%，剩下 80% 是工程化**。

作为架构师，你一定深有体会——没有 CI/CD、没有监控、没有灰度发布的系统不可能上线。AI 系统也是一样，只是多了数据漂移、模型衰减、幻觉检测这些独特挑战。

这课帮你把之前学到的所有模型知识，连接到真实的生产系统。

## 核心概念解释

### MLOps = DevOps + 数据 + 模型

| DevOps | MLOps |
|--------|-------|
| 代码版本管理 | **代码 + 数据 + 模型** 三重版本管理 |
| CI/CD | **CT (Continuous Training)** + CI/CD |
| 服务监控 | **模型性能监控** + 服务监控 |
| 灰度发布 | **A/B 测试 + 影子模式** |
| 回滚 | **模型回滚 + 数据回滚** |

### ML 系统的隐藏技术债

Google 经典论文指出：ML 代码只占整个系统的很小一部分。真正的工程挑战在数据管道、特征工程、部署服务、监控告警等基础设施。

### 4 种部署策略

1. **蓝绿部署**：新旧版本并存，一键切换
2. **金丝雀发布**：逐步放量，降低风险（推荐）
3. **A/B 测试**：同时对比，数据驱动决策
4. **影子模式**：新版本接收流量但不返回结果，用于验证

### LLM 时代的 MLOps 新挑战

| 维度 | 传统 ML | LLM 时代 |
|------|---------|----------|
| 部署单位 | 模型权重 | Prompt + 模型 + RAG 管道 |
| 版本管理 | 模型版本 | Prompt + 模型 + 知识库 |
| 主要成本 | 训练 | **推理**（token 计费） |
| 监控重点 | 准确率 | 幻觉率、拒答率、成本 |

## 直觉理解

想象你开了一家餐厅（AI 系统）：
- **训练模型** = 研发出一道好菜 → 这是 20% 的工作
- **MLOps** = 确保这道菜每天稳定出餐、食材新鲜、顾客反馈持续改进 → 这是 80% 的工作
- **数据漂移** = 顾客口味变了，但你的菜谱没变 → 需要检测和调整
- **金丝雀发布** = 新菜品先给 5% 的顾客试吃 → 没问题再全量上线

## 关键机制

### 数据漂移检测
- 统计方法：KS 检验、PSI（Population Stability Index）、Jensen-Shannon Divergence
- 触发条件：分布偏移超过阈值 → 自动触发重训练 Pipeline

### 模型监控指标
- **性能指标**：准确率、F1、延迟（P50/P99）
- **LLM 特有**：幻觉率、拒答率、token 消耗、成本/请求
- **数据质量**：输入分布、缺失率、异常值
