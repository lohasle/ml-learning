# 2026年5月1日 - 第23课：AI系统设计与部署

## 今日学习主题
**理解一个训练好的 AI 模型如何变成可靠、可观测、可持续迭代的线上服务——模型服务架构、A/B 测试、数据漂移检测、监控告警、成本优化、安全防护的完整工程体系。**

## 为什么学这个？
上一课（大模型训练与推理工程）我们学会了怎么把模型训练出来、怎么让推理跑得快。但一个残酷的现实是：**能跑的模型 ≠ 能用的产品**。

从架构视角看，前 22 课我们一直在学「算法和架构」层面的知识。但作为一个架构师，你不仅需要知道怎么设计模型，还需要知道怎么设计和运维一个完整的 AI 系统——从模型上线到持续监控，从版本管理到安全防护。

**在 AI 演进中的位置**：AI 系统工程（2015-）是与模型创新并列的关键能力。Google 2015 年的论文「Hidden Technical Debt in Machine Learning Systems」揭示了一个重要事实——机器学习系统中，ML 代码只占整个系统的很小一部分，周围环绕着庞大的基础设施。2023-2024 年的 LLM 浪潮更是把模型服务、RAG 管线、Agent 编排等系统工程推向了前台。**能设计一个可靠的 AI 系统，是一个架构师的核心竞争力。**

本课是整个学习路线的**收官之课**——从第 1 课的线性回归到今天的系统设计，完成从「理解算法」到「构建系统」的完整闭环。

## 核心概念解释

### 1. 模型服务架构——三种核心模式
- **直觉**：部署一个模型就像开一家餐厅——你可以做快餐（在线推理，下单即取）、外卖（异步推理，下单等配送）、或者卖预制菜（边缘部署，客户带回家自己做）。
- **在线推理**：请求到达 → 模型推理 → 即时返回。延迟敏感（通常 < 200ms），如搜索排序、实时推荐。代表：Triton、TF Serving。
- **异步推理**：请求到达 → 排队处理 → 回调返回。延迟容忍（秒级到分钟级），如 LLM 文本生成、图像/视频处理。代表：Celery + vLLM。
- **边缘部署**：模型打包到终端设备。低延迟、离线可用、隐私友好，但受限于设备算力。代表：ONNX Runtime Mobile、CoreML。

### 2. MLOps 与模型生命周期
- **直觉**：传统软件的 CI/CD 是「代码变更 → 自动测试 → 自动部署」。MLOps 额外多了一个维度——**数据和模型也在持续变化**。
- **核心流程**：数据收集 → 特征工程 → 模型训练 → 评估 → 模型注册 → 部署 → 监控 → 漂移检测 → 触发重训练 → 循环
- **与 DevOps 的关键区别**：
  - DevOps：代码变更触发部署
  - MLOps：**数据变更**和**模型退化**也会触发重新训练和部署
  - 需要额外的模型注册中心（Model Registry）来管理模型版本
- **代表工具**：MLflow（实验跟踪+模型管理）、Kubeflow（K8s 原生 ML 管线）、Weights & Biases（实验可视化）

### 3. A/B 测试——模型迭代的标准方法
- **直觉**：就像药物临床试验——新药先给少数人试用，证明有效且安全后再大规模推广。新模型也一样，先小流量验证，统计显著后再全量切换。
- **核心流程**：流量分流（90% → A，10% → B）→ 收集指标（准确率、延迟、转化率）→ 统计检验（t-test / 卡方检验）→ 决策
- **关键陷阱**：
  - 样本量不足导致假阳性（需要统计功效分析确定最小样本量）
  - 网络效应：A/B 组用户之间可能互相影响
  - 新奇效应：新功能上线初期的效果可能不持久
- **代码对应**：Notebook 模拟了完整的 A/B 测试过程，包含统计显著性检验。

### 4. 数据漂移检测——AI 系统的隐形杀手
- **直觉**：你训练了一个「夏天穿衣推荐」模型，冬天上线——数据分布完全不同，模型预测质量必然崩塌。更隐蔽的是缓慢漂移——用户行为每月变化一点点，积累半年后模型就失效了。
- **三种漂移类型**：
  - **协变量漂移（Covariate Shift）**：输入 X 的分布变了（用户群体变化）
  - **概念漂移（Concept Drift）**：P(Y|X) 的关系变了（疫情前后的消费行为完全不同）
  - **标签漂移（Label Shift）**：输出 Y 的分布变了（正负样本比例变化）
- **检测指标**：PSI（Population Stability Index）
  - PSI < 0.1 → 稳定 ✅
  - PSI 0.1~0.25 → 轻微漂移，需关注 ⚠️
  - PSI > 0.25 → 严重漂移，需重新训练 🔴
- **代码对应**：Notebook 中的 PSI 计算和漂移可视化。

### 5. 监控与可观测性
- **直觉**：传统软件监控看 CPU/内存/延迟。AI 系统还需要监控「预测质量」——模型在跑，但预测对不对？
- **关键指标四层模型**：
  1. **系统层**：延迟（P50/P99）、QPS、错误率、GPU 利用率
  2. **模型层**：预测准确率、置信度分布、输出分布
  3. **数据层**：特征分布、输入异常检测、漂移指标（PSI）
  4. **业务层**：转化率、用户满意度、A/B 测试指标
- **告警策略**：不只要看绝对值，还要看趋势——准确率的缓慢下降比突变更危险
- **代表工具**：Prometheus + Grafana（系统监控）、Evidently AI（ML 专用监控）、自定义仪表板

### 6. 成本优化——GPU 很贵，省着用
- **直觉**：推理就像打车——你不能为了一个人包一辆大巴，也不能让 100 个人挤一辆出租车。关键是在 SLA（服务质量）和成本之间找到最优平衡。
- **六大优化策略**：
  - **量化**（INT4/INT8）：成本降 2-4x，精度损失可控
  - **动态批处理**：把多个请求打包一起推理，吞吐量提升 3-5x
  - **弹性伸缩**：低峰缩容，高峰扩容，节省 30-60% 空闲成本
  - **模型蒸馏**：大模型教小模型，推理成本降 10x+
  - **Speculative Decoding**：小模型猜、大模型验，延迟降 2-3x
  - **语义缓存**：相似查询直接返回缓存结果，命中率 70%+ 即可大幅降本

### 7. AI 安全防护
- **直觉**：AI 系统上线后就像一个对外开放的 API——任何人都可以尝试利用它的弱点。
- **五大安全风险**：
  - **Prompt 注入**：用户通过精心构造的输入操控模型行为（越狱攻击）
  - **数据泄露**：模型在输出中暴露训练数据中的敏感信息
  - **幻觉输出**：模型生成看似合理但完全错误的内容
  - **对抗样本**：微小扰动输入导致模型严重误判
  - **供应链攻击**：恶意模型或数据注入系统
- **防护原则**：安全不是事后补丁，而是架构设计的一等公民。纵深防御——输入过滤 + 模型安全 + 输出校验 + 监控告警。

## 关键公式直觉

| 概念 | 公式/方法 | 直觉解释 |
|------|----------|----------|
| PSI | Σ(actual% - expected%) × ln(actual% / expected%) | 两个分布的「差异度」，越大越危险 |
| A/B 样本量 | N ≈ (Z_α + Z_β)² × 2p(1-p) / Δ² | 想检测的差异越小，需要的样本越多 |
| 缓存收益 | 节省成本 = 命中率 × 单次推理成本 × 请求量 | 命中率 70% 意味着 70% 的请求不需要推理 |
| GPU 成本 | 小时费率 × GPU 数 × 利用率 × 运行时长 | 利用率 50% 意味着你浪费了一半的钱 |
| P99 延迟 | 第 99 百分位的延迟值 | 100 个请求中最慢的那个的延迟 |
| 模型退化率 | d(accuracy)/dt | 准确率随时间下降的速度，决定重训练频率 |

## 常见问题

**Q: MLOps 和 DevOps 有什么本质区别？**
A: 核心区别在于**数据维度**。DevOps 的变更源是代码，MLOps 的变更源是代码 + 数据 + 模型。数据会漂移，模型会退化，这些都需要自动化的检测和响应机制。简单说：DevOps 是 CI/CD，MLOps 是 CI/CD + CT（Continuous Training）。

**Q: 一个小团队需要全套 MLOps 吗？**
A: 不需要。起步阶段只需要三样东西：1）模型版本管理（用 Git + MLflow 即可）；2）基本的上线监控（延迟 + 错误率）；3）一个简单的回滚机制。其他的（A/B 测试、漂移检测、自动重训练）随着规模和需求逐步添加。

**Q: LLM 应用的部署和传统 ML 模型有什么不同？**
A: 最大的不同是**延迟和成本**。传统 ML 模型推理通常 < 50ms，LLM 生成可能需要 2-10 秒。这意味着：1）必须用异步架构（流式输出）；2）必须做成本优化（量化 + 缓存几乎标配）；3）幻觉检测比准确率监控更重要；4）Prompt 管理成为新的「配置管理」。

**Q: 怎么判断一个模型需要重新训练了？**
A: 三个信号：1）PSI > 0.25（数据严重漂移）；2）准确率持续下降超过预期波动范围；3）业务指标（如转化率）无明显原因下降。建议设一个自动化流水线：当任一信号触发时，自动用最新数据重训练并评估。

## 本课总结
1. **AI 系统不只是模型 + API**：完整的系统需要监控、版本管理、A/B 测试、漂移检测、安全防护等工程体系
2. **三种服务模式各有所长**：在线推理（低延迟）、异步推理（高吞吐）、边缘部署（隐私/离线）
3. **数据漂移是隐形杀手**：用 PSI 等指标持续监控，超过阈值自动触发重训练
4. **A/B 测试是科学迭代**：小流量验证、统计显著后全量切换，避免主观决策
5. **成本优化是组合拳**：量化 + 缓存 + 弹性伸缩 + 蒸馏，根据业务 SLA 选择最优组合
6. **安全是架构的一等公民**：纵深防御，从设计阶段就考虑输入过滤、输出校验、监控告警
7. **从第 1 课到第 23 课的完整闭环**：线性回归 → 深度学习 → Transformer → LLM → 多模态 → 训练工程 → 系统设计 → 你现在能设计和构建一个完整的 AI 系统了
