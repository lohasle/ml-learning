# 2026年5月9日 - 第31课：推测解码（Speculative Decoding）

## 今日学习主题

**推测解码：如何让大模型「猜得快又准」——用小模型当助手，大模型并行验证，突破自回归串行瓶颈**

## 为什么学这个？

上一课（第30课 量化推理技术）我们学会了用更少的 bit 表示模型参数，减少了**每次前向传播的计算量**。但大模型推理还有另一个根本瓶颈：**自回归的串行依赖**——生成 100 个 token 就需要 100 次串行前向传播。

推测解码回答了：**能不能不改模型权重，不改精度，只改生成策略，就让推理快 2~3 倍？**

答案是肯定的。Speculative Decoding 已被 Google、Meta、DeepSeek 等广泛采用，是 2023-2025 年 LLM 推理优化的核心突破之一。

## 这个知识点在 AI 演进中的位置

- **前序知识**：第30课的量化压缩了每次前向的计算量
- **本课**：推测解码减少了前向传播的**次数**
- **历史位置**：2023 年由 DeepMind 和 Google 分别提出（Leviathan et al., Chen et al.），迅速成为 LLM serving 标配
- **后续连接**：推测解码 + 量化 + 蒸馏 的组合是当前 LLM 部署的最佳实践

## 核心概念解释

### 1. 自回归瓶颈

- **直觉**：想象你在排队结账——每个人必须等前面的人结完才能开始。即使每个收银台很快，100 个人还是得排 100 次
- **问题本质**：GPU 可以一次处理很多 token（如 prefill 阶段），但 decode 阶段每次只能生成 1 个 token
- **关键公式**：自回归生成 $P(x_t | x_1, ..., x_{t-1})$，每步依赖上一步的输出

### 2. Draft-then-Verify 流程

```
Step 1: Draft 模型（7B）快速生成 K 个候选 token
Step 2: Target 模型（70B）一次前向传播，并行评估所有 K 个 token
Step 3: 按概率接受/拒绝，拒绝处重新采样
```

- **直觉**：就像让打字快的实习生先把邮件草稿打好，你扫一遍——对的留下，错的当场改。比你从头一个字一个字敲快得多
- **核心保证**：接受/拒绝的概率机制确保最终分布与纯 target 模型**完全一致**（零质量损失）

### 3. 接受概率的数学

对于候选 token $x$，接受条件：

$$\text{accept if } r < \min\left(1, \frac{p_{\text{target}}(x)}{p_{\text{draft}}(x)}\right)$$

其中 $r \sim \text{Uniform}(0,1)$

- **直觉**：如果 target 比 draft 更认可这个 token（比值 > 1），一定接受；如果 target 不太认可，按比例概率接受
- **关键**：draft 模型越接近 target → 接受率越高 → 加速比越大

### 4. 加速比分析

| 场景 | K（候选数） | 接受率 | 等效加速 |
|------|-----------|--------|---------|
| 理想对齐 | 5 | ~95% | ~4.5× |
| 实际常见 | 5 | ~80% | ~2.5-3× |
| 较差对齐 | 5 | ~50% | ~1.5-2× |
| 完全不对齐 | 5 | ~20% | ~1.0×（无收益）|

## 关键公式直觉

| 概念 | 公式 | 直觉解释 |
|------|------|----------|
| 自回归概率 | $P(x_t\|x_{<t})$ | 每个字只能看前面的字来猜 |
| 接受条件 | $r < p_t / p_d$ | target 说「好」就留，说「一般」就碰运气 |
| 理论加速 | $\approx K \cdot \alpha + 1$ | K 个候选 × 接受率 + 1 个 bonus token |
| Draft 成本 | $C_{\text{draft}} / C_{\text{target}}$ | 小模型快多少倍（通常 10-50×） |

## 常见问题

**Q: 推测解码会降低生成质量吗？**
A: 不会。接受/拒绝的概率机制保证最终分布与纯 target 模型完全一致。这是推测解码最大的优势——免费加速，零质量损失。

**Q: Draft 模型怎么选？**
A: 通常选同系列的小模型（如 LLaMA-7B 配 LLaMA-70B）。关键是分布要对齐，而不是参数越多越好。也有方法不用单独的 draft 模型（如 Medusa、Self-Speculative）。

**Q: 推测解码什么时候不适用？**
A: 两个场景：(1) batch inference 时，每个请求的接受 token 数不同，导致难以对齐；(2) draft 模型与 target 差异太大时，接受率低反而增加开销。

## 本课总结

1. 自回归生成的串行瓶颈是 LLM 推理慢的根本原因
2. 推测解码用小模型猜 + 大模型验，将串行变为半并行
3. 接受/拒绝机制保证零质量损失
4. 加速比取决于 draft-target 的分布对齐度（通常 2-3×）
5. 量化（减计算量）+ 推测解码（减次数）可叠加使用
