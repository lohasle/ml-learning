# 2026年5月12日 - 第34课：Prompt Engineering 高级技巧

## 今日学习主题

**Prompt Engineering：从「跟 AI 说人话」到「系统化接口设计」——5 种核心 Prompting 范式与工程化实践**

## 为什么学这个？

前 33 课我们已经学了 Transformer、大模型微调、RAG、Agent、推理优化、向量数据库、AI 安全等关键技术。但你有没有发现一个关键问题——**所有这些技术的效果，都取决于你怎么「问」模型**。

Prompt 就是人和大模型之间的接口层。好的 Prompt 能让同样的模型表现天差地别。这课不是教「写 prompt 的技巧」，而是教你把 Prompt 当作工程接口来设计——有模板、有测试、有版本管理。

- **后续连接**：Prompt 是后续 Agent 系统、RAG 系统、微调评估的基础接口

## 核心概念解释

### 1. Prompt 的本质：Latent Space 激活器

- **直觉**：大模型的参数里存储了海量知识和能力。Prompt 就是一把「钥匙」，决定打开哪扇门
- **类比**：大模型是一栋巨大的图书馆，Prompt 是你的检索词。精确的检索词能找到最相关的书，模糊的检索词可能找到一堆无关的
- **代码直觉**：Notebook 中的 MockLLM 演示了同一问题不同 Prompt 的响应质量差异

### 2. 五种核心 Prompting 范式

| 范式 | 一句话描述 | 关键魔法词 |
|------|-----------|-----------|
| **Zero-shot** | 直接问，不给示例 | 无 |
| **Few-shot** | 给 3-5 个示例 | `例如：...→...` |
| **CoT** | 让模型写推理步骤 | `一步步思考` |
| **ToT** | 探索多条路径再选最优 | `列出3个方案，评估可行性` |
| **ReAct** | 边想边做，循环推理 | `Thought → Action → Observation` |

### 3. 结构化 Prompt 的四要素

一个工程级的 Prompt 应该包含：

1. **角色设定**（Role）：你是谁
2. **任务描述**（Task）：做什么
3. **约束条件**（Constraints）：不能做什么 / 边界
4. **输出格式**（Format）：以什么形式回答

```
角色：你是一个专业的 Python 代码审查专家
任务：审查以下代码片段，找出 bug 和性能问题
约束：只关注逻辑错误和性能，不讨论代码风格
格式：用 JSON 输出 [{line, issue, severity, suggestion}]
```

## 关键公式直觉

| 概念 | 核心思想 | 直觉解释 |
|------|----------|----------|
| Few-shot | $P(y|x, E_1...E_k)$ | 给 $k$ 个示例 $(E)$ 后，模型对输入 $x$ 的输出质量更高 |
| CoT | $P(a|q) = \prod P(r_i|r_{<i}, q) \cdot P(a|r, q)$ | 先生成推理链 $r_1...r_n$，再基于推理链给答案 $a$ |
| ToT | $\text{argmax}_a \sum_{\text{path}} V(\text{path})$ | 同时探索多条路径，选择评估价值 $V$ 最高的 |
| ReAct | $a_t = f(s_t, o_t)$ | 每步行动 $a$ 基于当前思考 $s$ 和观察 $o$ 决定 |

## 动手实践要点

- **Notebook 实验1**：对比 Zero-shot 和 Few-shot 对同一问题的响应差异
- **Notebook 实验2**：体验 CoT 对推理质量的提升
- **Notebook 实验3**：构建可复用的 PromptTemplate 类
- **参数选择**：Few-shot 示例数量 3-5 个最佳，不要超过 10 个
- **常见坑点**：Prompt 中包含矛盾指令会让模型输出不可预测

## 常见问题

**Q: Prompt 越长效果越好吗？**
A: 不是。过长的 Prompt 会稀释关键信息，模型可能「迷失」在上下文中。关键是精确和结构化，不是长度。研究表明 200-500 词的结构化 Prompt 通常效果最好。

**Q: Few-shot 的示例从哪里来？**
A: 三个策略：① 手工挑选覆盖边界情况的典型案例；② 从训练集/历史数据中用 embedding 相似度自动检索；③ 用模型自己生成示例（Self-Generated CoT）。示例的质量 >> 数量。

**Q: 怎么评估 Prompt 的好坏？**
A: 三步法：① 建立测试集（正常 + 边界 + 对抗样本）；② 定义评估指标（准确率/格式合规率/延迟）；③ A/B 对比不同 Prompt 版本。DSPy 框架可以自动化这个流程。

## 本课总结

1. Prompt 不是「说话技巧」，是人和大模型之间的「API 接口设计」
2. 5 种范式（Zero-shot → Few-shot → CoT → ToT → ReAct）覆盖从简单到复杂的所有场景
3. 工程化的 Prompt 有四要素：角色 + 任务 + 约束 + 格式
4. CoT（「一步步思考」）是万能增强器，几乎适用于所有推理任务
5. 好的 Prompt 需要测试驱动，不是一次写成的
