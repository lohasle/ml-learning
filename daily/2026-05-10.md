## 今日学习主题

**向量数据库与嵌入检索：现代 AI 应用的「记忆系统」——把语义变成向量，用数学找回相关知识**

## 为什么学这个？

前面我们学了 RAG（第19课）、Agent（第20课）和大模型推理优化（第30-31课）。这些系统都依赖一个底层基础设施：**向量数据库 + 嵌入检索**。

## 核心概念解释

### 1. 嵌入（Embedding）：文本的数学表示

- **直觉**：像给每个词语/句子发一个「语义身份证」——意思相近的身份证号也接近
- **本质**：用一个高维向量（768/1024/1536维）来表示文本的语义
- **类比**：GPS 坐标能表示地理位置关系，嵌入向量能表示语义关系

```
"猫"  → [0.23, -0.15, 0.89, ...]  ← 动物区
"狗"  → [0.21, -0.13, 0.91, ...]  ← 动物区（很近！）
"汽车" → [-0.45, 0.67, -0.12, ...] ← 交通区（很远）
```

### 2. 相似度检索：从向量找回语义

| 度量方式 | 公式 | 直觉 |
|----------|------|------|
| 余弦相似度 | $\cos(\theta) = \frac{\vec{a} \cdot \vec{b}}{|\vec{a}||\vec{b}|}$ | 方向越一致越相似 |
| 欧氏距离 | $d = \|\vec{a} - \vec{b}\|$ | 空间距离越小越相似 |
| 内积 | $\vec{a} \cdot \vec{b}$ | 归一化后等价余弦 |

- **关键**：归一化向量上，余弦相似度和欧氏距离是等价的
- **实践**：大多数向量数据库默认使用余弦相似度或内积

### 3. ANN 索引：速度与精度的平衡

精确搜索 100 万个向量没问题，但 10 亿个就慢了。ANN（近似最近邻）通过牺牲微小精度换取巨大速度提升：

| 算法 | 原理 | 适合规模 | 特点 |
|------|------|----------|------|
| Flat | 暴力搜索 | <100万 | 最准，最慢 |
| IVF | 聚类+局部搜索 | 100万~1亿 | 速度精度可调 |
| HNSW | 多层图结构 | 100万~1亿 | 查询最快，内存大 |
| PQ | 向量量化压缩 | >1亿 | 省内存，有损 |

### 4. 主流向量数据库

| 数据库 | 定位 | 特色 |
|--------|------|------|
| FAISS | 库 | Meta开源，研究首选，纯向量搜索 |
| Milvus | 分布式数据库 | 生产级，支持十亿级，丰富的过滤 |
| Pinecone | 全托管服务 | 零运维，快速上线 |
| Chroma | 嵌入式数据库 | 轻量，适合原型开发 |
| Weaviate | 全功能数据库 | 支持 GraphQL，内置向量化和搜索 |

## 关键公式直觉

| 概念 | 公式 | 直觉解释 |
|------|------|----------|
| 余弦相似度 | $\cos = \frac{a \cdot b}{\|a\|\|b\|}$ | 两个方向的重合程度 |
| L2 距离 | $\|a - b\|_2$ | 两点间的直线距离 |
| HNSW 查询复杂度 | $O(\log N)$ | 像查字典，不用翻遍每一页 |
| PQ 压缩率 | $D \times 4B / (M \times 8B)$ | 128维float32→16字节，压缩32× |
| 混合检索分数 | $\alpha \cdot S_{vec} + (1-\alpha) \cdot S_{BM25}$ | 向量+关键词加权融合 |

## 一个完整的 RAG 检索流程

```
1. 文档分块（Chunking）
   "长文档" → ["chunk1", "chunk2", "chunk3", ...]

2. 嵌入生成（Embedding）
   "chunk1" → [0.23, -0.15, 0.89, ...]

3. 向量索引（Indexing）
   存入向量数据库，构建 ANN 索引

4. 相似度检索（Retrieval）
   query → embed → 搜索 Top-K → 返回最相关的 K 个 chunk

5. 注入 LLM（Generation）
   retrieved chunks + query → LLM → 回答
```

## 关键工程决策

| 决策 | 推荐 | 原因 |
|------|------|------|
| 中文嵌入模型 | BGE-large-zh | 中文语义理解最好 |
| 分块大小 | 256-512 tokens | 太小丢失上下文，太大稀释语义 |
| 检索 Top-K | 3-10 | 生产环境通常 5 个 |
| 是否重排序 | 是（Reranker） | 初检索粗筛 + 精排，精度提升明显 |
| 纯向量 vs 混合 | 混合 | 关键词匹配+语义理解互补 |

## 相关关键项目

- **FAISS** (2019)：Meta 开源，向量检索的「标准工具箱」
- **Milvus** (2019)：Zilliz 开源，生产级分布式向量数据库
- **Sentence-Transformers** (2019)：HuggingFace 生态的嵌入模型库
- **LangChain** (2022)：集成向量数据库的 RAG 开发框架

## 今天学完后你应该记住什么

1. **嵌入** = 文本 → 向量，是向量检索的基础
2. **余弦相似度**是最常用的相似度度量
3. **ANN 索引**用微小精度损失换数量级速度提升（HNSW/IVF/PQ）
4. **向量数据库选型**取决于规模、运维能力和功能需求
5. **混合检索**（BM25 + 向量）是生产环境的最佳实践
6. 向量数据库是 RAG 和 AI Agent 的核心基础设施
