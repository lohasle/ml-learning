# 2026年5月6日 - 第28课：MoE（混合专家模型）与稀疏激活架构

## 今日学习主题
**MoE（Mixture of Experts）—— 用「条件计算」让大模型参数多但不贵**

## 为什么学这个？

昨天学了高效微调技术（LoRA/QLoRA/DPO），解决了「大模型推理部署太贵」的问题。今天从另一个角度解决同样的问题——**架构层面**的效率优化。

MoE 不是微调技巧，而是模型架构本身的设计：让模型拥有海量参数（知识容量大），但每次推理只激活一小部分（计算成本低）。GPT-4、Mixtral、DeepSeek-V3 都采用了 MoE 架构——理解 MoE，就是理解当前最先进大模型的底层设计。

### 与前一课的关系
- 第27课（高效微调）：降低**微调**和**部署**成本
- 第28课（MoE）：从**架构**层面降低推理成本，同时保持大参数量
- 两者常常结合使用：MoE 模型 + LoRA 微调

## 核心概念解释

### 1. 条件计算（Conditional Computation）

**直觉**：不是所有知识都需要用于每个输入。

一家大医院有心脏科、骨科、眼科、皮肤科等 8 个专科。来个病人，不需要 8 个科都看一遍，分诊台（门控网络）根据症状把病人送到最合适的 2 个科。

**对应到模型**：
- 传统 Dense 模型：所有参数（所有医生）参与每次推理（每次会诊）
- MoE 模型：门控网络根据输入 token 选择 2 个专家（2 个科室），只计算这 2 个

### 2. 门控网络（Router / Gating Network）

**直觉**：分诊台的护士——快速判断应该去哪个科。

**工作原理**：
1. 输入 token → 线性变换 → 得到每个专家的分数
2. 取分数最高的 K 个（通常 K=2）
3. Softmax 归一化 → 得到权重
4. 加权组合 K 个专家的输出

### 3. 稀疏激活（Sparse Activation）

**关键洞察**：MoE 模型可能有 47B 总参数（如 Mixtral 8x7B），但每次推理只用约 13B 参数。这就是「参数多但不贵」的秘密。

公式直觉：
- 总参数量 = N × 单专家参数量（全部知识）
- 每次推理计算量 = K × 单专家参数量（实际调用）

## 关键公式直觉

| 概念 | 公式/方法 | 直觉解释 |
|------|-----------|----------|
| MoE 输出 | MoE(x) = Σ g_i(x) · E_i(x) | 选中专家的加权组合 |
| 门控概率 | g_i = softmax(W_g · x)_i | 给每个专家打分，归一化为概率 |
| Top-K 选择 | 选概率最高的 K 个专家 | 不是全选，只选最匹配的 |
| 负载均衡损失 | L_bal = N · Σ(f_i · P_i) | 防止所有 token 都挤向同一个专家 |
| DeepSeek 偏置调整 | 不加辅助损失，用可学习偏置调节 | 更优雅的负载均衡方案 |

## 动手实践要点

Notebook 中的关键步骤：

1. **Expert 类**：一个简单的两层 FFN（ReLU 激活），这就是「专家」
2. **TopKGating 类**：线性变换 → Top-K → Softmax，这是「分诊台」
3. **MoELayer 类**：组合门控 + 专家，记录路由历史
4. **负载均衡实验**：用 Dirichlet 分布模拟三种路由均衡程度，观察辅助损失值的变化
5. **参数效率对比**：可视化 MoE vs Dense 在不同专家数量下的参数对比

### 常见坑点

- **路由坍缩**：训练初期所有 token 都涌向少数专家，其他专家得不到训练 → 加辅助损失
- **All-to-All 通信**：分布式训练时，token 需要跨 GPU 发送到对应专家 → 通信开销
- **专家同质化**：训练不充分时，不同专家学到了相似的功能 → 需要更多数据和更长训练

## 常见问题

**Q: MoE 和集成学习（Ensemble）有什么区别？**
A: 集成学习中所有模型都参与推理，结果取平均/投票。MoE 只激活一部分专家，不是全部参与，是「动态选择」而非「全部组合」。MoE 更像是「根据情况请不同的专家」，集成是「所有专家都请来开会」。

**Q: 为什么通常选 top-2 而不是 top-1 或 top-4？**
A: Top-1 太稀疏，训练不稳定（梯度信号弱），且 token 只经过一个专家，缺少不同视角的融合。Top-4 以上计算成本上升，收益递减。Top-2 是实践中效果和效率的平衡点。不过 DeepSeek-V3 用了 top-8，说明如果专家粒度够细（更多但更小的专家），多选几个也可以。

**Q: MoE 模型能做 LoRA 微调吗？**
A: 可以，而且很常见。通常只对门控网络和选中的专家做 LoRA 适配，共享专家可以冻结。这正是 MoE + LoRA 的组合优势。

## 本课总结

1. **MoE 的核心思想是条件计算**：不是所有参数参与每次推理，根据输入动态选择专家
2. **门控网络是关键组件**：学会把 token 路由到最合适的专家，训练时需要负载均衡
3. **MoE 让「大参数 + 低成本」成为可能**：总参数可以很大（知识多），但每次推理只激活一小部分
4. **当前最先进的大模型大多采用 MoE**：GPT-4、DeepSeek-V3、Mixtral 等
5. **工程挑战主要是通信和负载均衡**：分布式训练的 All-to-All 通信是瓶颈
