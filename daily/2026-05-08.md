# 2026年5月8日 - 第30课：量化推理技术

## 今日学习主题

**量化推理技术（Quantization）：如何用更少的 bit 表示模型——大模型从云端走向终端的关键技术**

## 为什么学这个？

上一课（第29课 知识蒸馏与模型压缩）我们学会了「大模型→小模型」的知识迁移。但即使是蒸馏后的小模型，在 FP16 精度下仍然很大（7B 模型约 14GB）。

**量化回答了另一个关键问题**：能不能不改模型结构，只改数值的表示方式，就把模型缩小 2~8 倍？

答案是肯定的。量化是大模型部署中最广泛使用的压缩技术，几乎所有从云端到终端的部署方案都离不开它。

## 这个知识点在 AI 演进中的位置

- **前序知识**：第29课的知识蒸馏已经减少了模型参数量
- **本课**：量化进一步压缩每个参数的存储位数
- **历史位置**：量化并不是 LLM 时代的发明——CNN 时代就有了 INT8 量化（如 TensorRT）。但 LLM 的权重分布有独特的「离群值」问题，催生了 GPTQ、AWQ 等新方案
- **后续连接**：量化 + 蒸馏 + 剪枝的组合是模型压缩的完整工具箱

## 核心概念解释

### 1. 量化的基本原理

- **直觉**：量化就像把一张 32-bit 的无损音频压缩成 8-bit 的 MP3——信息有损，但人耳几乎听不出区别
- **核心操作**：将浮点数映射到有限个整数级别
- **关键公式**：

$$x_{quantized} = \text{round}\left(\frac{x}{scale}\right) + \text{zero\_point}$$

$$x_{dequantized} = (x_{quantized} - \text{zero\_point}) \times scale$$

- **代码对应**：Notebook 中的 `uniform_quantize()` 函数

### 2. PTQ vs QAT

| 维度 | PTQ（训练后量化） | QAT（量化感知训练） |
|------|-------------------|---------------------|
| 时机 | 训练完成后 | 训练过程中 |
| 成本 | 低，少量校准数据 | 高，完整训练 |
| 精度 | INT8 损失极小 | 更优，补偿量化误差 |
| 适用 | 大多数部署场景 | 极致精度要求 |

**类比**：PTQ 像是「后期转码」——视频拍完后压缩；QAT 像是「拍摄时就考虑压缩」——从源头减少信息损失。

### 3. 离群值问题（LLM 量化的最大挑战）

- **现象**：LLM 的权重中约有 0.1% 的极端值，远超正常范围
- **影响**：朴素量化会被这些离群值「绑架」——为了覆盖极端值，scale 变大，普通值的精度反而变差
- **解决方案**：
  - **GPTQ**：用 Hessian 信息逐列优化量化误差
  - **AWQ**：识别重要通道并做缩放保护
  - **SmoothQuant**：把激活离群值「迁移」到权重上

### 4. 主流量化格式

| 格式 | 特点 | 适用场景 |
|------|------|----------|
| GPTQ | 二阶优化，需校准数据 | GPU 推理 |
| AWQ | 保护 salient 通道 | GPU 推理 |
| GGUF | CPU/GPU 混合，llama.cpp 生态 | 本地部署 |
| SmoothQuant | W8A8 全 INT8 | 服务器推理 |

## 关键公式直觉

| 概念 | 公式 | 直觉解释 |
|------|------|----------|
| 对称量化 scale | $s = \frac{\max(\|W\|)}{2^{b-1}-1}$ | 浮点范围除以整数范围，得到「每个整数级别代表多大的浮点间距」 |
| 量化操作 | $q = \text{round}(w / s)$ | 浮点值除以 scale 再取整，落入最近的整数级别 |
| 反量化 | $\hat{w} = q \times s$ | 整数乘回 scale，恢复浮点近似值 |
| 量化误差 | $\epsilon = w - \hat{w}$ | 原始值与恢复值之差，是量化的信息损失 |
| AWQ 缩放 | $s_c = \text{opt}(c)$ for salient $c$ | 重要通道的权重在量化前先放大，量化后精度更好 |

## 动手实践要点

- Notebook 中的 `uniform_quantize()` 实现了完整的量化-反量化流程
- 关键参数：`n_bits`（量化位数）直接影响精度和压缩比
- INT8 几乎无损（余弦相似度 > 0.999），INT4 有轻微损失但可接受
- 离群值会让朴素量化效果变差，AWQ 的通道保护策略可以缓解
- 实际部署中，GPTQ/AWQ 的效果远好于朴素量化

### 常见坑点

1. **量化不是越少 bit 越好**：INT2 通常精度损失严重，INT4 是实用下限
2. **校准数据很重要**：PTQ 需要少量代表性数据来校准 scale 和 zero_point
3. **不同层的敏感度不同**：注意力层通常比 FFN 层更敏感，可能需要混合精度

## 常见问题

**Q: 量化和蒸馏有什么区别？**
A: 蒸馏是训练一个参数更少的新模型（结构变化）；量化是不改变模型结构，只改变数值表示方式（精度变化）。两者互补：先蒸馏得到小模型，再量化进一步压缩。

**Q: 为什么 LLM 的量化比 CNN 难？**
A: LLM 权重中有少量极端离群值（可能达正常值的 100 倍），这些离群值会破坏朴素量化的精度。CNN 的权重分布更均匀，INT8 量化几乎无损。

**Q: GGUF 和 GPTQ 我应该选哪个？**
A: 如果用 GPU 推理（如 vLLM），选 GPTQ 或 AWQ；如果用 CPU 或本地部署（如 Ollama），选 GGUF。GGUF 的生态更友好，GPTQ/AWQ 的 GPU 性能更好。

**Q: 量化会影响模型的推理能力（如数学推理）吗？**
A: 会有影响。量化主要影响的是「精细判断」能力，INT4 量化后的模型在数学推理、代码生成等任务上可能有轻微下降。这也是为什么 QAT 和混合精度量化仍然重要的原因。

## 本课总结

1. 量化通过降低数值精度（FP32→INT8/INT4）实现模型压缩，不改模型结构
2. INT8 量化几乎无损，INT4 是实用精度的下限，INT2 通常损失过大
3. LLM 量化的核心挑战是权重离群值，GPTQ/AWQ/SmoothQuant 各有妙招
4. PTQ 简单快速，QAT 精度更高，大多数部署场景 PTQ 足够
5. 量化与蒸馏、剪枝组合使用，是大模型落地的完整压缩工具箱
