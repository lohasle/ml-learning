# 大模型训练与推理工程

## 🎯 核心概念

### 1. 基础定义
- **类型**：系统工程 / 分布式计算
- **适用场景**：训练或部署参数量超过单卡显存容量的模型
- **一句话定义**：用分布式策略和压缩技术，让超大模型在多 GPU 上高效训练和推理

### 2. 核心工程挑战
- **训练侧**：显存墙（单卡装不下）+ 通信瓶颈（GPU 间数据传输慢）
- **推理侧**：显存带宽瓶颈（模型大 → 每次生成都要读大量权重）+ 延迟/吞吐权衡
- **核心公式**：训练显存 ≈ 参数量 × 2B(FP16权重) + 参数量 × 8B(Adam优化器) + 参数量 × 2B(梯度) + 激活值

### 3. 并行策略
- **数据并行（DDP/FSDP）**：每卡持有完整模型或分片，处理不同数据
- **张量并行（TP）**：同一层的权重矩阵按列/行切分到多卡
- **流水线并行（PP）**：不同层分配到不同卡，数据依次流过
- **3D 并行**：TP(节点内) + PP(跨节点) + DP(扩规模)

### 4. 推理优化
- **KV Cache**：缓存历史 token 的 K/V 向量，避免重复计算
- **量化（INT8/INT4）**：降低权重精度，减少显存和带宽需求
- **Continuous Batching**：动态组批，提高 GPU 利用率
- **PagedAttention (vLLM)**：分页管理 KV Cache，避免显存碎片

## 📊 关键公式

| 公式 | 含义 | 直觉 |
|------|------|------|
| 训练显存 ≈ 20B × 参数量 | 一个参数训练时占 ~20 bytes | Adam 的 3 个状态各占一些 |
| KV Cache = 2 × L × d × seq_len × batch × 2B | 推理缓存的显存 | K 和 V 各一份，长序列时很大 |
| 量化后大小 = 原大小 × (原位数/新位数) | INT4 = FP16 的 1/4 | 压缩比就是位数比 |
| AllReduce 通信 = 2 × 模型大小 × (N-1)/N | DDP 梯度同步开销 | N 越大，每卡分摊越少 |

## 💡 记忆技巧
训练 = 「搬箱子」——太大搬不动就拆开（TP）、分批运（PP）、叫更多人帮忙（DP）。
推理 = 「读笔记」——不用每次重读全部历史（KV Cache），也不用逐字精读（量化）。
